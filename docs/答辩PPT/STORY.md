# STORY.md — 聊天智能分析助手（ChatMonitor）答辩

## ① 用户意图对齐

- **目标受众**：科创比赛评委（可能包含信息技术教师、科技专家）。场合为现场答辩演示，评委关注：项目的真实性、技术含量、工程完成度、创新性与实用价值。
- **核心目标**：让评委相信——① 这是**真实开发、真实联调、真实运行**的完整系统（不是演示壳）；② 技术架构有深度（多进程/多平台/双级判定/SSE/安全加固）；③ 解决的是校园真实痛点；④ 作者具备系统性工程能力。
- **PPT 长度**：14 页（封面 1 + 目录 1 + 章节扉页 3 + 正文 8 + 结束 1）。Hero 页配额 3 页（封面、测试验证、总结展望），占比约 21%。
- **视觉调性**：学术严谨 / 蓝白克制 / 数据支撑 / 简洁可信（命中学术风预设）。
- **内容边界**：
  - 必讲：背景痛点、总体架构（多进程）、三大核心技术（双级判定 / SSE 推送 / 文件库三路 AI）、多用户与安全、创新点、测试验证（44 项 + 真实联调）。
  - 不讲：部署细节（实名认证等与答辩无关）、超算资源、聊天监控的合规争议细节。
  - 禁碰：夸大宣传、虚构数据；所有测试数字均真实（44 项测试、16 类 288 词词库、2 秒 SSE、PBKDF2、JWT 等）。
