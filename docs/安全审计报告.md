# ChatMonitor 安全审计技术报告

- 审计日期：2026-09-05
- 审计范围：Web 服务（`web/`）、核心模块（`core/`）、入口（`config.py`/`launcher.py`/`main.py`）、平台接入层（`platforms/`）、移动端（`mobile/`）、依赖与部署配置（`requirements.txt`、`configs/`、`deploy/`）
- 审计方式：静态代码审计 + git 跟踪状态核查 + 依赖漏洞库比对
- 结论摘要：共发现 **高危 4 项、中危 15 项、低危 10 项**。系统整体架构健康（密码哈希、回调验签、参数化 SQL、CSRF 防护等均规范），但**多租户路径边界**存在两个可叠加利用的高危漏洞，任何访客注册账号即可读取全站凭据与聊天记录，须立即修复。

---

## 一、高危漏洞（须立即修复）

### H1. 注册用户名无字符校验 → 多租户路径穿越

- 位置：`core/accounts/users.py:21-26`、`config.py:160-167`、`web/routers/files.py:20-24`
- 问题：注册仅校验用户名长度（3–32），不校验字符集；用户名直接拼接为文件系统路径（`data/users/{username}/`）。
- 影响：注册默认开放（`REGISTER_OPEN=true`，`config.py:100`），攻击者注册 `../users/victim` 之类用户名后，可通过正常 API 读取**任意受害者的消息库与媒体文件**；注册 `../../x/y` 则以服务权限在任意可写位置创建目录和 SQLite 文件。
- 修复：`create_user` 增加白名单 `re.fullmatch(r"[A-Za-z0-9_-]{3,32}", username)`；`user_data_dir()` 等路径函数增加 resolve 后仍在 `DATA_DIR` 内的断言（纵深防御）。

### H2. `/api/media/raw` 路径穿越 → 任意登录用户可拖库

- 位置：`web/routers/files.py:15-28`
- 问题：仅做字符串前缀检查 `path.startswith(f"users/{uname}/media/")`，resolve 后只校验"在 `data/` 内"。传入 `users/<自己>/media/../../../users.db` 即可通过全部校验。
- 影响：`data/users.db` 含**所有用户的密码哈希与全部平台绑定密钥**（QQ/钉钉/飞书 AppSecret、企微 AES Key），`data/*.db` 含全部群聊消息。与 H1/注册开放叠加，等于全站凭据与隐私完全失守。
- 修复：resolve 后校验目标必须位于 `DATA_DIR/users/{uname}/media/` 之内；直接拒绝含 `..` 的输入；`api_file_raw`（files.py:71）一并加 resolve 校验。

### H3. 存储型 XSS：AI 输出 `priority` 未校验 + 总览页未转义渲染

- 位置：`core/analyzer.py:141`、`web/static/js/pages/overview.js:89`（另 `core/reporter.py:128` 未转义但有 CSP 兜底）
- 问题：`alerts.priority` 直接取 AI 输出入库，无白名单；总览页 `innerHTML` 拼接未转义。AI 输入来自群聊消息，即**群内任何成员可通过提示注入控制该字段**。
- 影响：被监控群中的攻击者可注入恶意 HTML/JS，管理员打开"总览"页即触发，可携带管理员 cookie 调用任意 API（改密、导出消息）。
- 修复：入库前白名单化（`priority if priority in ("high","medium","low") else "medium"`）；overview.js 改用 `esc()`；reporter.py 同步转义。

### H4. 移动端全局允许明文 HTTP

- 位置：`mobile/android/app/src/main/AndroidManifest.xml:20`（`usesCleartextTraffic="true"`）、`mobile/lib/state/app_state.dart:104,122`（裸地址自动补 `http://`）
- 影响：用户在不可信网络下使用 HTTP 地址时，登录密码、JWT token、各平台 App Secret 均可被嗅探/篡改。
- 修复：移除 `usesCleartextTraffic`（或用 `networkSecurityConfig` 仅放行调试域名）；默认补 `https://`；nginx 强制 80→443 并开启 HSTS。

## 三、低危问题（摘要）

- 报告路径白名单 `startswith` 无分隔符边界（`web/deps.py:122-124`），建议 `Path.is_relative_to()`
- `/api/platforms/{name}/pending` 泄露全局命令队列给任意登录用户（`web/routers/platforms.py:33-36`）
- 主应用无安全响应头（`web/server.py:33-39`），建议统一中间件
- 改密码接口无单独限流（`web/routers/account.py:24-38`）
- 聊天内容 PII 明文进入 stdout 日志与第三方 LLM（`core/pipeline.py:87` 等），推送异常日志可能含 `SERVERCHAN_KEY` URL
- 收件箱 `scope`（corpid）未做字符清洗即拼路径（`core/inbox.py:30-31`）
- LIKE 查询未转义 `%`/`_` 通配符（`core/storage/messages.py:44-46`、`core/storage/files.py:44-46`）
- access_token 置于 URL query，异常日志可能携带完整 URL（`platforms/dingtalk.py:88,181`、`platforms/workwechat.py:45-47`）
- 媒体默认文件名使用未净化的 msg_id（`core/media.py:76`）
- 日报 WebView 未限制导航（`mobile/lib/pages/reports_page.dart:183-191`）；QQ 媒体下载失败日志打印含 rkey 的 URL（`platforms/qq.py:221`）

## 四、良好实践（值得保留）

- **密码存储**：PBKDF2-HMAC-SHA256、10 万轮、每用户随机盐、`hmac.compare_digest` 常量时间比较；改密后 `password_version+1` 使旧 JWT 失效
- **JWT 加固**：默认/空 `JWT_SECRET` 启动时自动随机化并回写；Cookie `HttpOnly + SameSite=lax`，`Secure` 可配置；FastAPI 仅监听 127.0.0.1、`docs_url=None`
- **CSRF/CORS**：非 GET 校验 Origin 同源；无 CORS 中间件（默认不跨域）；登录按 IP+用户名双维度限流，且只信 Nginx 写入的 `X-Real-IP`
- **SQL**：全部参数化查询，未发现注入；全项目无 `eval/exec/pickle/shell=True`
- **企微回调**：验签 + AES-256-CBC + CorpID 校验、常量时间比较、拒绝 DTD 防 XXE、验签失败限流——实现规范
- **密钥卫生**：git 历史与当前跟踪中无任何真实 `.env`/`.db`/私钥（`git ls-files` 确认）；平台密钥 API 回显统一脱敏；四平台 token 仅内存缓存、提前刷新、不落盘
- **出站 TLS**：未发现 `verify=False`，所有出站端点均 HTTPS；SSE 需登录、按用户隔离、限制连接数

## 五、修复优先级路线图

1. **立即（P0）**：H1 用户名白名单正则（一行修复）、H2 媒体接口 resolve 后目录边界校验、H3 priority 白名单 + `esc()`——三处均为小改动，堵住"注册即拖库"完整攻击链
2. **一周内（P1）**：M13 `.gitignore` 通配（防下一次密钥误提交）、M1/M2/M3/M4（鉴权与信息泄露）、M7（admin 随机盐 + 强制改默认口令）、H4 移动端 HTTPS
3. **排期（P2）**：M5 更新流程可信化、M6 密钥加密存储、M8/M15 部署加固、M14 依赖锁定 + CI 接入 `pip-audit`/`osv-scanner`、其余低危项

> 遗留说明：本次审计时 WebSearch 服务故障，除 CVE-2024-53981 经 OSV 确认外，其余依赖版本的最新 CVE 状态建议用 `pip-audit` 在本地复核。当前 `.venv` 实装版本（fastapi 0.141.1、pycryptodome 3.23.0、cryptography 50.0.1 等）均高于已知历史高危的修复版本，当前环境不受影响，风险主要在依赖未锁定。
